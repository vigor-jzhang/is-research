# Publication Formatting, Export & Submission Package — Phase 4C

Phase 4C transforms an immutable `ManuscriptDraft` into a publication-ready
manuscript and submission package:

```text
ManuscriptDraft (4B)
→ citation/bibliography resolution (CitationReference → PaperIdentity → PaperRecord)
→ FormattedManuscript (front matter, ordered sections, inline citations)
→ deterministic validation
→ exports: Markdown / LaTeX / DOCX / PDF (BlobStore)
→ SubmissionPackage (+ optional CoverLetter)
```

Formatting never changes research conclusions; journal submission automation
is out of scope.

## Schemas (`src/research_harness/research/schemas/publication.py`)

- `PublicationProfile` — journal/style name, citation style, required
  sections, section order, per-section + total word limits, abstract
  requirements, anonymous-review mode, free-form formatting rules.
  Configurable — never hard-coded to one journal.
- `Bibliography` / `BibliographyEntry` — canonical references deduplicated by
  `PaperIdentity`, rendered per style.
- `FormattedManuscript` — front matter (title/abstract/keywords), ordered
  `FormattedSection`s (body with inline citations, word counts,
  conditions-preserved flags), bibliography, `citation_map` (citation id →
  paper identity id, kept after rendering), validation status + issues.
- `SubmissionPackage` — formatted manuscript + `ExportRecord`s (+ optional
  cover letter); status `ready` only when validation passed and all exports
  succeeded.
- `CoverLetter` — structured, same anti-overclaiming rules.
- `PublicationExecution` — operational record.

## Citation / bibliography pipeline

Internal `[CITE:<id>]` placeholders resolve through the section's
`CitationReference` → `PaperIdentity` → first `PaperRecord` in the identity.
Inline citations render as `(Author and Author, Year, p. X)`; bibliography
entries render from available DOI/title/authors/year/venue fields ONLY —
missing fields are omitted, never invented. References are deduplicated by
`PaperIdentity` (multiple citation ids → one entry). The `citation_map`
retains citation → identity ids so internal provenance survives rendering.

## Publication profiles

`publication profile-create --name ... [--style author_year|apa]
[--anonymous] [--total-word-limit N] [--abstract-max-words N]`. Citation
styles are behind a replaceable `CitationStyle` contract
(`publication_formatter/styles.py`) — `author_year` (default) and `apa`
implement it; journal-specific styles can be added without touching the
formatter.

## Export architecture

`ManuscriptExporter` protocol (`contracts/manuscript_exporter.py`) with
deterministic renderers registered as `manuscript_exporter.<format>`:
Markdown, LaTeX (`\documentclass` per profile rules), DOCX (python-docx),
PDF (reportlab). All rendered bytes go to the BlobStore (content-addressed
sha256); `ExportRecord`s hold `format`, `renderer/version`, `blob_ref`,
`content_hash`, `size_bytes`, `source_draft_id`, `profile_id`. Binary
DOCX/PDF never enter SQLite JSON. Rendering is deterministic — cross-run
comparison matches modulo run-specific artifact UUIDs.

## Anonymous-review mode

When the profile sets `anonymous_review`, authors/affiliations/acknowledgements
are emptied deterministically (front matter, cover letter, LaTeX `\author{}`);
scholarly citations are NOT altered. Validation flags any leak.

## Abstract and front matter

Title/abstract/keywords are generated by the configurable `reasoning` role,
grounded ONLY in the final manuscript content (bounded prompt with abstract
max words); global-novelty phrasing is stripped and validated away. No new
findings or novelty claims can appear.

## Cover letter

Optional (`package --cover-letter`): structured `CoverLetter` from the
manuscript + contribution claims; summarizes contributions and journal fit
under the same anti-overclaiming rules (novelty normalization, deterministic
validation).

## Final publication validation (deterministic)

- unresolved citations (placeholder without a declared citation) and
  leftover `[CITE:...]` placeholders in output;
- bibliography covers every cited paper; no unused entries required by the
  profile;
- required sections present; section ordering follows the profile;
- per-section + total word limits; abstract max words;
- anonymous-review violations;
- unsupported novelty language in abstract/title;
- conditions unchanged (claims grounded in verified propositions re-checked
  against the propositions).

A failed validation sets `validation_status=failed` (superseding artifact);
the SubmissionPackage is only `ready` when validation passed and all four
exports succeeded.

## Provenance

```text
SubmissionPackage → FormattedManuscript (supersedes chain for validation)
  → ManuscriptDraft → ManuscriptSection → ResearchResultsPackage
  → verified research artifacts
Bibliography → PaperIdentity → PaperRecord
ExportRecord → FormattedManuscript (format, renderer/version, blob ref,
  content hash, source draft id, profile id)
CoverLetter → FormattedManuscript + ContributionClaims
```

## CLI

```bash
uv run research-agent publication profile-create --name "MIS Quarterly (generic)"
uv run research-agent publication format --draft <draft-id> --profile <profile-id>
uv run research-agent publication validate <manuscript-id>
uv run research-agent publication export --manuscript <manuscript-id> --format latex
uv run research-agent publication package --manuscript <manuscript-id> [--cover-letter]
uv run research-agent publication inspect <package-id>
```

## Tests

Unit (`tests/unit/test_publication.py`, 11): citation resolution + inline
rendering; bibliography deduplication by identity; missing metadata without
fabrication; unresolved citation rejection (validation fails, placeholders
flagged); anonymous mode (citations untouched); condition preservation
(dropped conditions → `conditions_changed`); Markdown/LaTeX/DOCX/PDF export
content checks; BlobStore persistence (hash round-trip); deterministic
rerender (idempotent export, cross-store bytes identical modulo UUIDs);
section ordering + word limits; front matter novelty normalization; package
provenance after reopen; failed validation → package not ready.

Integration (`tests/integration/test_phase4c_publication.py`): full offline
chain — draft → format (citations resolved, dedup) → bibliography → validate
→ all four exporters → SubmissionPackage (ready) with provenance after
reopen.

Live (`tests/live/test_publication_live.py`, opt-in `live_publication`): uses
the live manuscript draft; LLM limited to front matter; exports deterministic.
Live run: 3 sections, 113 words, LLM-generated abstract + 6 keywords, all 4
exports in the BlobStore, package `ready`.

## Limitations

- Citation styles implement generic author-year + basic APA; full APA rules
  and journal-specific style sheets are future work behind the contract.
- Author names are rendered as stored (no initials/abbreviation logic).
- PDF/DOCX exports are single-font, minimal styling (no journal templates).
- The DOI is never verified/expanded; missing fields are omitted, which may
  produce sparse references for sparse records.
- Abstract grounding is prompt-constrained + novelty-validated, not
  semantically verified against the manuscript.
- Export bytes for PDF/DOCX depend on library versions; reproducibility is
  pinned to the recorded renderer versions.

## Recommendation for post-Phase-4 work

- **Novelty validation phase**: verify global-novelty claims against
  external corpora before any real submission (the harness currently only
  normalizes/rejects them).
- Journal-specific style sheets and template-based DOCX/LaTeX rendering.
- DOI/Crossref metadata enrichment with explicit provenance for augmented
  fields.
- Persistent author/affiliation management (profile-level author records).
- A reviewer-facing artifact trail (findings → manuscript sections →
  evidence) already exists via provenance and could power a reproducibility
  appendix.
